# 06 — ระบบข้อมูลและการอัปเกรด LINE Bot

เอกสารนี้เชื่อม Workflow เข้ากับโค้ดที่มีอยู่จริงในโปรเจกต์นี้

**สิ่งที่มีอยู่แล้ว:**
- `app/api/line-webhook/route.ts` — รับ webhook จาก LINE, ตรวจ signature, ตอบข้อความ
- `lib/gemini.ts` — เรียก Gemini พร้อม timeout 8 วิ และ fallback เป็น `DEFAULT_REPLY`
- `lib/sheet.ts` — ดึง FAQ จาก Google Sheet (CSV) พร้อม cache 60 วิ และ fallback เป็น cache เก่า
- `lib/line.ts` — ตรวจ signature + ส่งข้อความตอบกลับ
- `lib/constants.ts` — ค่าคงที่และ env

**ข้อจำกัดปัจจุบัน:** บอทตอบได้เฉพาะ FAQ ตอบเสร็จแล้วข้อมูลหายไป ไม่มีการเก็บ Lead ไม่รู้ว่าคุยกับใคร และไม่มีสถานะการสนทนา

## 6.1 โครงสร้าง Google Sheet (8 แท็บ)

ไฟล์ CSV ต้นแบบอยู่ใน [`templates/`](templates/) — คัดลอกหัวคอลัมน์ไปสร้างแท็บได้เลย

| แท็บ | ใช้ทำอะไร | สเตจ | ใครแก้ |
|---|---|---|---|
| `faq` | FAQ ให้บอทตอบ (**มีอยู่แล้ว**) | S6 | Admin |
| `properties` | ทะเบียนบ้านทุกหลัง สถานะ ราคา เกรดน้ำ ต้นทุน | S1–S8 | เจ้าของ, Reno PM |
| `leads` | ลูกค้าทุกคน + เกรด A/B/C/D + สถานะในท่อ | S6 | Admin, Sales |
| `credit_cases` | เคสปั้นเครดิต แผน 90 วัน ผลการยื่นกู้ | S7 | Credit Officer |
| `deals` | ดีลที่จับคู่ลูกค้า×บ้านแล้ว จนถึงวันโอน | S8 | Sales |
| `reno_tasks` | งานรีโนเวทรายรายการ BOQ vs จริง | S4 | Reno PM |
| `sourcing_pipeline` | ทรัพย์ที่กำลังพิจารณา + คะแนน + MAO | S1–S2 | เจ้าของ, Scout |
| `comps` | ฐานราคาปิดขายจริง ← สินทรัพย์ระยะยาว | S2 | เจ้าของ |
| `content_calendar` | ปฏิทินคอนเทนต์ + ผลลัพธ์ | S5 | Content |

### สถานะมาตรฐาน (ใช้ให้ตรงกันทั้งระบบ)

**`properties.status`**
`sourcing` → `under_offer` → `owned` → `renovating` → `ready` → `listed` → `reserved` → `sold` → `dropped`

**`leads.stage`**
`new` → `contacted` → `qualified` → `viewing_booked` → `viewed` → `credit_program` → `loan_submitted` → `approved` → `closed_won` / `closed_lost` / `nurture`

**`leads.grade`** — `A` / `B` / `C` / `D` (ดู [02-workflow.md](02-workflow.md) §6.3)

**`properties.flood_grade`** — `A` / `B` / `C` / `D` / `E` (ดู [01-strategy.md](01-strategy.md) §1.3)

## 6.2 แผนอัปเกรด LINE Bot — 5 เฟส

### เฟส 1 — ให้บอทรู้จักบ้านที่มีจริง (ง่ายที่สุด ผลตอบแทนสูงสุด)

**ปัญหาปัจจุบัน:** บอทตอบได้แค่ FAQ ถ้าลูกค้าถาม *"มีบ้านแถวควนลังไหม"* บอทตอบไม่ได้

**วิธีทำ:** เพิ่มการดึงแท็บ `properties` (เฉพาะแถวที่ `status = listed`) มาต่อท้าย context ใน prompt

```
โครงสร้าง prompt ใหม่ใน lib/gemini.ts

<faq>            ...เหมือนเดิม...            </faq>
<properties>     บ้านที่พร้อมขายตอนนี้ (จาก Sheet)  </properties>
```

**สิ่งที่ต้องระวังในการแก้:**
- ข้อจำกัดใน prompt ปัจจุบันเขียนว่า *"ตอบโดยใช้ข้อมูลใน `<faq>` เท่านั้น"* → ต้องแก้ให้ครอบคลุม `<properties>` ด้วย
  ไม่งั้นบอทจะยังปฏิเสธที่จะตอบเรื่องบ้าน
- **ยังต้องคงข้อห้ามแต่งราคาเองไว้เด็ดขาด** — ราคาผิดในแชท = ปัญหาทางกฎหมายและความน่าเชื่อถือ
- ระวังขนาด context: `properties` โตขึ้นเรื่อยๆ ให้กรองเฉพาะ `status = listed` และตัดคอลัมน์ต้นทุนออก
  ⚠️ **ห้ามส่งคอลัมน์ราคาซื้อ/ต้นทุนรีโนเวท/กำไร เข้า prompt เด็ดขาด** — โมเดลอาจพูดออกไป
- `SHEET_CACHE_TTL_MS` ปัจจุบัน 60 วิ เหมาะกับ FAQ แต่ `properties` เปลี่ยนไม่บ่อย ตั้ง cache แยกได้

### เฟส 2 — เก็บ Lead เข้า Sheet อัตโนมัติ

**เป้าหมาย:** ทุกคนที่ทักเข้ามาต้องถูกบันทึก ไม่ใช่หายไปในแชท

**สิ่งที่ต้องเพิ่ม:**
1. เขียนข้อมูลกลับเข้า Sheet — ทางที่ง่ายที่สุดคือ **Google Apps Script Web App** ที่รับ POST แล้ว `appendRow`
   (ไม่ต้องตั้ง Service Account ให้ยุ่งยาก และไม่ต้องเก็บ private key ใน env)
2. ทุกครั้งที่มีข้อความเข้า → upsert แถวใน `leads` ด้วย `line_user_id` เป็นคีย์
3. เก็บ: `line_user_id`, ชื่อโปรไฟล์, เวลาที่ทักครั้งแรก, ข้อความล่าสุด, บ้านที่ถามถึง, ช่องทางที่มา

**สิ่งที่ต้องระวัง:**
- **ต้องขอความยินยอม PDPA ก่อนเก็บข้อมูลการเงิน** — ข้อมูลติดต่อพื้นฐานเก็บเพื่อตอบกลับได้ แต่รายได้/หนี้/บูโรต้องมีความยินยอมชัดเจน
- Route ปัจจุบันคืน 200 เสมอเพื่อกัน LINE retry — การเขียน Sheet ต้อง **ไม่ throw ออกมาทำให้ route พัง** ใช้รูปแบบ catch-and-log เหมือน `replyText` ที่มีอยู่
- อย่าให้การเขียน Sheet ทำให้ตอบช้า — LINE reply token หมดอายุเร็ว **ตอบลูกค้าก่อน แล้วค่อยเขียน Sheet**
- URL ของ Apps Script ต้องเก็บใน env (เช่น `SHEET_WRITE_URL`) + ใส่ shared secret กันคนอื่นยิง

### เฟส 3 — Rich Menu + Flow คำนวณ

**Rich Menu 6 ช่อง:**

| ช่อง | ไปที่ไหน |
|---|---|
| 🏠 บ้านพร้อมขาย | ส่ง Flex Message รายการบ้าน `status = listed` พร้อมการ์ดตัวเลข |
| 🧮 คำนวณค่าผ่อน | LIFF หรือหน้าเว็บ → กรอกราคาบ้าน → ค่าผ่อนโดยประมาณ |
| ✅ เช็คว่ากู้ได้เท่าไร | LIFF → กรอกรายได้+ภาระหนี้ → DSR + วงเงิน + เกรด A/B/C/D → บันทึกลง `leads` |
| 💰 เงินสดวันโอน | คำนวณค่าโอน จดจำนอง ประกัน มิเตอร์ |
| 📅 นัดดูบ้าน | ฟอร์มนัด → แจ้งเตือนกลุ่ม LINE ทีม |
| 💬 คุยกับแอดมิน | เปิดโหมดคนจริง (ดูเฟส 4) |

> ทุกเครื่องมือต้องมีข้อความขอความยินยอม PDPA ก่อนกดส่ง และต้องระบุว่าเป็น **การประมาณการเบื้องต้น ไม่ใช่การอนุมัติของธนาคาร**

### เฟส 4 — ส่งต่อให้คนจริง (Human Handover)

**ปัญหาที่จะเจอแน่นอน:** ลูกค้าคุยกับบอทอยู่ แล้วแอดมินเข้ามาตอบ → บอทตอบซ้อนทับ ลูกค้าสับสน

**วิธีแก้:**
1. เพิ่มฟิลด์ `human_mode` (พร้อม `human_mode_until`) ในแถว lead
2. เปิดโหมดคนเมื่อ: ลูกค้าพิมพ์คำว่า "แอดมิน" / "คุยกับคน" / "นัดดูบ้าน" หรือแอดมินกดเปิดเอง
3. ระหว่าง `human_mode = true` → **webhook ไม่เรียก Gemini เลย** แค่บันทึกข้อความ
4. ปิดอัตโนมัติเมื่อเงียบเกิน 2 ชั่วโมง หรือแอดมินกดปิด
5. เมื่อเปิดโหมดคน → **แจ้งเตือนเข้ากลุ่ม LINE ของทีมทันที** (นี่คือกลไกที่ทำให้ SLA 5 นาทีเป็นจริง)

### เฟส 5 — ติดตามอัตโนมัติ

- แจ้งเตือนแอดมินเมื่อมี lead ที่ยังไม่มีคนตอบเกิน 15 นาทีในเวลาทำการ
- ส่งข้อความติดตามอัตโนมัติที่ +3 / +10 / +30 วัน (ดูสคริปต์ใน [04-marketing-and-scripts.md](04-marketing-and-scripts.md) §4.5.6)
- Broadcast บ้านใหม่เฉพาะกลุ่มที่โซนและงบตรงกัน (ไม่ยิงทุกคน — ยิงมั่วทำให้คนบล็อก)
- แจ้งเตือน Credit Officer เมื่อถึงกำหนดติดตามเคสปั้นเครดิต

## 6.3 สิ่งที่ต้องระวังในโค้ดปัจจุบัน (ก่อนต่อยอด)

| จุด | สถานะปัจจุบัน | ข้อควรพิจารณาเมื่อขยาย |
|---|---|---|
| `route.ts` คืน 200 เสมอ | ✅ ถูกต้องแล้ว — กัน LINE retry ซ้ำ | ต้องรักษาไว้เมื่อเพิ่มการเขียน Sheet ห้ามให้ error หลุดออกมา |
| `askGemini` fallback เป็น `DEFAULT_REPLY` | ✅ ดี | เมื่อมีหลาย flow ควรแยกข้อความ fallback ตามบริบท |
| `getFaqFromSheet` ใช้ stale cache เมื่อดึงไม่ได้ | ✅ ออกแบบดี | ใช้แนวเดียวกันกับ `properties` |
| ไม่มีการเก็บประวัติการสนทนา | ทุกข้อความเป็นเอกเทศ | ถ้าจะทำ flow คัดกรอง 7 คำถาม **ต้องมี state** — เก็บใน Sheet หรือ KV |
| ประมวลผลทุก event พร้อมกันด้วย `Promise.all` | ✅ | ระวัง rate limit ของ Sheet API เมื่อเพิ่มการเขียน |
| `GEMINI_TIMEOUT_MS = 8000` | เหมาะกับ FAQ | reply token ของ LINE หมดอายุเร็ว — อย่าเพิ่ม timeout ให้ยาวกว่านี้มาก |
| ไม่มี rate limit / ไม่มีการกันสแปม | — | เพิ่ม throttle ต่อ `line_user_id` ก่อนเปิดใช้จริงในวงกว้าง |

## 6.4 ข้อกำหนดด้านความปลอดภัยและ PDPA (บังคับ)

- [ ] **ห้ามส่งข้อมูลการเงินของลูกค้า (รายได้ หนี้ บูโร) เข้า prompt ของโมเดล** — ใช้เฉพาะข้อมูลสาธารณะของทรัพย์และ FAQ
- [ ] **ห้ามใส่คอลัมน์ต้นทุน/ราคาซื้อ/กำไร ของบ้าน ลงใน context ที่บอทเห็น**
- [ ] Google Sheet ที่มีข้อมูลลูกค้า **แชร์แบบระบุอีเมลรายบุคคลเท่านั้น** ห้าม "ใครมีลิงก์ก็เปิดได้"
- [ ] `SHEET_CSV_URL` ที่เผยแพร่แบบสาธารณะ ให้ใช้ได้เฉพาะกับแท็บ `faq` และ `properties` ที่กรองคอลัมน์แล้ว
- [ ] มีข้อความขอความยินยอม PDPA ใน Rich Menu และก่อนทุกฟอร์มที่เก็บข้อมูลการเงิน
- [ ] มีนโยบายความเป็นส่วนตัวบนเว็บไซต์ + ลิงก์ใน LINE OA
- [ ] Secrets ทั้งหมดอยู่ใน env (ตามที่ `.env.example` ทำอยู่แล้ว) **ห้าม commit ค่าจริง**
- [ ] บอทต้องมีข้อความกำกับเสมอว่า **ตัวเลขที่คำนวณเป็นการประมาณการ ไม่ใช่การอนุมัติของธนาคาร**
- [ ] กำหนดระยะเวลาเก็บข้อมูลและกระบวนการลบเมื่อลูกค้าขอ
