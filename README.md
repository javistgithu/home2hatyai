# ระบบ POS อุปกรณ์ไฟฟ้าและโคมไฟ

ระบบขายหน้าร้านและจัดการสต๊อกตามตำแหน่งเก็บ สำหรับร้านเดียวที่มีหน้าร้าน
สโตร์หลังร้าน และจุดโชว์โคมไฟ

## ปัญหาที่ระบบนี้แก้

> "ระบบบอกว่ามีของ แต่พอไปหยิบจริงหาไม่เจอ"

ระบบสต๊อกทั่วไปตอบได้แค่ *"มีกี่ชิ้น"* ซึ่งไม่พอ พนักงานต้องรู้ว่า
*"อยู่ช่องไหน"* ด้วย ถ้าตอบไม่ได้ ก็ต้องเดินหาเหมือนเดิม

ระบบนี้จึงยึด 3 หลักตั้งแต่ระดับฐานข้อมูล:

| หลักการ | ผลที่ได้ |
|---|---|
| ยอดสต๊อกผูกกับ **ช่องเก็บ** เสมอ ไม่ใช่ผูกกับสินค้าเฉยๆ | ค้นสินค้าปุ๊บ รู้เลยว่าอยู่ `S-A2-3` กี่ชิ้น |
| ทุกการเปลี่ยนยอดต้องมีบรรทัดใน **บัญชีเดินสะพัด** (เขียนอย่างเดียว) | ตอบได้ว่ายอดเพี้ยนตอนไหน ใครทำ เอกสารใบไหน |
| **ตัวโชว์อยู่คนละช่อง** กับของขาย และหยิบอัตโนมัติไม่ได้ | ระบบไม่บอกว่ามี 1 ชิ้น ทั้งที่ชิ้นนั้นแขวนโชว์อยู่ |

---

## เริ่มใช้ภายใน 1 นาที

ไม่ต้องติดตั้งฐานข้อมูล ระบบใช้ PGlite (Postgres ที่รันในตัวเอง) ตอนทดลอง

```bash
npm install
npm run db:reset     # สร้างตาราง + ใส่ข้อมูลตัวอย่าง 31 รายการ 115 ช่องเก็บ
npm run dev
```

เปิด http://localhost:3000 แล้วเข้าสู่ระบบ

| รหัสพนักงาน | PIN | สิทธิ์ |
|---|---|---|
| `OWNER` | `246810` | เจ้าของร้าน (อนุมัติราคาพิเศษ / ยกเลิกบิลได้) |
| `S01` | `1357` | พนักงาน |
| `S02` | `2468` | พนักงาน |

> **ข้อควรระวังตอน dev:** PGlite เก็บข้อมูลเป็นไฟล์ในโฟลเดอร์ `.pgdata`
> และเปิดได้ **ทีละโปรแกรมเท่านั้น** ต้องปิด `npm run dev` ก่อนรัน `npm run db:*`
> ไม่งั้นทั้งสองฝั่งจะเห็นข้อมูลคนละชุด แล้วงานที่บันทึกระหว่างนั้นจะหายเงียบๆ
> ข้อจำกัดนี้ไม่มีผลกับการใช้งานจริงที่ต่อ Postgres

## หน้าจอทั้งหมด

| หน้า | ใครใช้ | ใช้ทำอะไร |
|---|---|---|
| **งานวันนี้** `/pos` | ทุกคน | รายการงานค้างที่ทำเสร็จได้ใน 5 นาที + ยอดขายวันนี้ |
| **ขายของ** `/pos/sell` | พนักงาน | ยิงบาร์โค้ด → เลือกระดับราคา → รับเงิน จบ |
| **ของอยู่ไหน** `/pos/find` | ทุกคน | ค้นแล้วรู้ทันทีว่าอยู่ช่องไหน กี่ชิ้น ตัวโชว์อยู่จุดไหน + ปุ่ม **หาไม่เจอ** |
| **นับสต๊อก** `/pos/count` | ทุกคน | ยิงป้ายชั้น → นับ → ปรับยอด (1 ช่อง ≈ 1 นาที) |
| **รับของ** `/pos/receive` | ทุกคน | รับของเข้าโดย**บังคับระบุช่องเก็บ** |
| **ตัวโชว์** `/pos/display` | ทุกคน | ผังจุดโชว์ + โคมที่ยังไม่มีตัวโชว์ + รอบตรวจสภาพ |
| **พิมพ์ป้าย** `/pos/labels` | เจ้าของ | พิมพ์บาร์โค้ดติดชั้นวางและสินค้า |

## ระบบรหัสตำแหน่ง

```
S - A2 - 3
│   │    └── ช่องที่ 3 (นับจากซ้ายไปขวา เมื่อยืนหันหน้าเข้าชั้น)
│   └─────── ชั้นวาง A ชั้นที่ 2 (นับจากล่างขึ้นบน)
└─────────── โซน: F = หน้าร้าน, S = สโตร์หลังร้าน, D = จุดโชว์
```

นับจากล่างขึ้นบนและซ้ายไปขวา เพราะเป็นทิศที่คนมองโดยธรรมชาติ
ถ้าสลับทิศ พนักงานจะหยิบผิดช่องแล้วโทษว่าระบบผิด

ช่องพิเศษที่ทุกร้านมี:

| รหัส | ใช้ทำอะไร |
|---|---|
| `F-TMP` | จุดพักของที่ยังไม่ได้เก็บเข้าชั้น — ขึ้นเตือนทุกวันจนกว่าจะย้าย |
| `S-DMG` | ของเสีย/รอเคลม — ระบบไม่นับเป็นของพร้อมขาย |
| `S-RSV` | ของที่ลูกค้าวางมัดจำไว้ — ห้ามหยิบขายคนอื่น |

## ราคา 5 ระดับ

| ระดับ | ชื่อ | ใช้กับใคร |
|---|---|---|
| 5 | ราคาเต็มก่อนลด | ราคาป้าย ใช้โชว์ว่าลดให้เท่าไหร่ |
| 1 | **ราคาขายจริง** | ลูกค้าทั่วไป (ค่าตั้งต้นของทุกบิล) |
| 2 | ราคาช่าง | ช่างไฟที่ซื้อประจำ |
| 3 | ราคาช่างขายส่ง | ช่าง/ร้านที่ซื้อไปขายต่อ |
| 4 | ราคาพิเศษ | ต่ำสุดของร้าน — **ต้องให้เจ้าของกด PIN อนุมัติทุกครั้ง** |

> เลขระดับ **ไม่ได้เรียงตามราคา** ระดับ 5 แพงสุด ระดับ 4 ถูกสุด
> โค้ดทุกที่ห้ามสมมติว่า level มาก = ถูกกว่า

ระบบตรวจให้อัตโนมัติว่าตั้งราคาสลับช่องหรือเปล่า (เช่น ราคาช่างแพงกว่าราคาปลีก)

## กลไกที่ทำให้สต๊อกแม่นขึ้นเอง

1. **ปุ่ม "หาไม่เจอ"** — กดครั้งเดียว ระบบบอกช่องอื่นที่มีของ, เตือนถ้าที่เห็นคือตัวโชว์,
   และเปิดงานนับช่องนั้นให้อัตโนมัติ พร้อมเก็บสถิติว่าช่องไหนมีปัญหาบ่อย
2. **ขายเกินยอดได้ แต่ตั้งธง** — ของอยู่ในมือลูกค้าแล้ว ห้ามขายไม่ได้
   ระบบจึงขายให้ ทำยอดติดลบให้เห็นชัด แล้วดันช่องนั้นขึ้นคิวนับอันดับหนึ่ง
   *(การบล็อกการขายคือวิธีที่ทำให้พนักงานหนีไปเขียนใส่กระดาษ แล้วสต๊อกเพี้ยนหนักกว่าเดิม)*
3. **นับหมุนเวียนทีละช่อง** — ไม่ต้องปิดร้านนับทั้งวัน วันละ 3 ช่อง ช่องละ 1 นาที
4. **นับแบบปิดยอด** — ไม่โชว์ยอดระบบตอนนับ กันการกรอกตามยอดโดยไม่ได้นับจริง
5. **บังคับระบุช่องตอนรับของ** — จุดที่ตำแหน่งของหายไปจากระบบมากที่สุด
6. **ตัวโชว์แยกช่อง** — จุดโชว์ตั้ง `is_pickable = false` ระบบจึงเลือกไปตัดขายไม่ได้เลย

## ใช้งานจริง (production)

```bash
# 1. สร้างฐานข้อมูล Postgres (Neon / Supabase / เครื่องที่ร้าน)
export DATABASE_URL="postgresql://..."
export POS_SESSION_SECRET="$(openssl rand -base64 32)"

# 2. สร้างตาราง (ไม่ใส่ข้อมูลตัวอย่าง)
npm run db:migrate

# 3. สร้างผังชั้นวางและผู้ใช้จริง แล้วพิมพ์ป้ายติดชั้น
npm run build && npm start
```

ตัวแปรที่ต้องตั้ง:

| ตัวแปร | จำเป็น | ใช้ทำอะไร |
|---|---|---|
| `DATABASE_URL` | ใช่ | ไม่ตั้ง = ใช้ PGlite ซึ่งห้ามใช้จริงบน serverless (ข้อมูลหาย) |
| `POS_SESSION_SECRET` | ใช่ | กุญแจเซ็น cookie เซสชัน |
| `DB_POOL_MAX` | ไม่ | จำนวน connection สูงสุด (ค่าเริ่มต้น 10) |

**ลำดับการเปิดใช้งาน** ดูที่ [`docs/rollout.md`](docs/rollout.md) —
สำคัญมากถ้าพนักงานไม่ค่อยชอบการเปลี่ยนแปลง

## คำสั่ง

```bash
npm run dev         # เซิร์ฟเวอร์ตอนพัฒนา
npm run build       # build สำหรับใช้งานจริง
npm test            # เทสต์ตรรกะธุรกิจ 116 รายการ (ใช้ฐานข้อมูลในหน่วยความจำ)
npm run db:migrate  # สร้าง/อัปเดตตาราง
npm run db:seed     # ใส่ข้อมูลตัวอย่าง
npm run db:reset    # ล้างแล้วสร้างใหม่ (เฉพาะตอน dev)
npm run db:status   # ดูสถานะฐานข้อมูล
```

app/api/pos/       API
